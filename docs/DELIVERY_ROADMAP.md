**Purpose:** Replace local-only state as the system of record and establish the trust boundary.

- Select a maintainable supported server/runtime and relational database based on deployable infrastructure, not convenience in this sandbox.

## Execution plan — follow in order; keep open until every release gate passes

This is the work order for continuing Slink. At each step, finish the work possible in this workspace, record evidence and limitations here, then continue to the next independent item. A feature is not accepted because its screen or route exists or because syntax is valid. Never seed customer stores with demo sales, store money as floating point, claim provider success from operator input, or call the product ready while any release gate lacks evidence.

1. **Close store onboarding and data entry.** Build a server-backed catalog/opening-stock import with preview, row-level validation, duplicate handling, idempotent submission, atomic stock ledger writes, and a downloadable template. Then cover customer/supplier opening balances or explicitly scope them out with a migration plan. **Pass evidence:** a representative store setup and import succeeds; malformed/duplicate input is clearly reported without partial business writes; integer VND and stock ledgers reconcile; replay is safe; another store cannot read or import the records.
2. **Finish core workflow correctness.** Close sales, payment, return/refund, purchase/payable, count, cashbook and report boundary cases, plus cashier cash reconciliation and audit attribution. **Pass evidence:** independent ledger reconciliation, duplicate/retry behavior, permission failures, concurrent stock/payment attempts and rollback cases all pass on a production-compatible database.
3. **Prove production data architecture.** Run migrations and the core workflow suite against native PostgreSQL using a least-privilege application role; prove two-store isolation, concurrency, restart, backup and restore. **Dependency:** accessible PostgreSQL environment and credentials. Continue implementation locally while this is unavailable; do not treat PGlite as equivalent evidence.
4. **Make mobile use and recovery dependable.** Verify responsive workflows, touch/keyboard/accessibility, install/update behavior and receipt/barcode paths on iOS and Android 10+. Design offline actions explicitly; implement a durable queue only with per-operation idempotency, server acknowledgement, conflict and recovery UX. **Dependency:** representative devices or approved device automation. Never advertise offline sales before reconnection reconciliation passes.
5. **Complete security, privacy and service operations.** Review tenant/role boundaries, abuse limits, secret handling, personal-data flows, retention/deletion, monitoring, incident response, support, backup schedule and recovery drills. Obtain authoritative Vietnamese legal/provider review before regulated claims. **Dependencies:** production-like environment, operational owner and competent review.
6. **Integrate and commercialize honestly.** Connect only selected payment/bank QR, e-invoice, email, shipping/accounting and Slink subscription providers; implement failure, retry, refund/webhook and reconciliation paths. **Dependencies:** provider accounts, sandbox credentials, approved terms and authorized external changes.
